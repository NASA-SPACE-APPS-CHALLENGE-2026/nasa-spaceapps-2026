# PlotTwist data sources (Milestone 1)

PlotTwist asks the farmer only for a field's shape and its crop history. Everything else in the **field profile** is fetched automatically, server-side, from public services that need no API key. Each source is a separate module in `lib/sources/` behind one interface (`ProfileSource.run`), runs in its own API request (`POST /api/profile/<source>`), and turns every failure into an `unavailable` result with a plain-language message. One source going down never affects the others.

## Provider matrix

| Source (module) | Provider and endpoint | What PlotTwist shows | Cache | Live test (2026-11-14) |
|---|---|---|---|---|
| Weather & climate (`power.ts`) | NASA POWER daily point API `power.larc.nasa.gov/api/temporal/daily/point` (T2M_MAX, T2M_MIN, PRECTOTCORR, community AG) and climatology point API (T2M, PRECTOTCORR, 1991–2020) | Rain over the latest 30 complete days vs the 1991–2020 normal for the same dates; average daily high and low; temperature vs normal; growing degree days (°F, base 50, 86 cap) | Daily: 6 h. Climatology: 30 days | Works, ~1 s. Latest day is a `-999` fill value (POWER lags a few days); it is dropped. Climatology `T2M_MAX` returns the *extreme* maximum, not the mean daily high, so normals use `T2M`. |
| Soil (`ssurgo.ts`) | USDA NRCS Soil Data Access `sdmdataaccess.sc.egov.usda.gov/Tabular/post.rest` (SQL with SDA spatial macros) | Main soil map unit and its share of the field; surface texture; area-weighted surface organic matter; drainage class; hydrologic soil group | 30 days | Works, 0.2–1.7 s. Empty result is `{}`; errors are HTTP 400 with an XML `ServiceException` body. |
| Elevation & slope (`elevation.ts`) | USGS Elevation Point Query Service `epqs.nationalmap.gov/v1/json` (3DEP) | Average elevation and height difference over up to 9 points inside the field; average slope from a least-squares plane | 1 year per point | Works but flaky: 0.2–17 s per point, instant HTTP 500s and 29 s HTTP 504 timeouts even for sequential calls. Requests run 3 at a time; fast 5xx errors are retried twice; the card says how many points could not be read. |
| Crop history (`cdl.ts`, via `POST /api/cdl`) | USDA NASS Cropland Data Layer via CropScape `nassgeodata.gmu.edu/axis2/services/CDLService` | Prefills prior seasons (2008–2025) with the dominant CDL class and its share | 30 days | `GetCDLValue` (point, EPSG:5070 x/y) works, 3–7 s. `GetCDLStat` and `GetCDLFile` (area queries) **timed out after 90–110 s**. PlotTwist tries the area clip first (20 s timeout, then a 10-minute circuit breaker) and falls back to sampling up to 5 points inside the field. A year is prefilled only when one class covers at least half the samples; otherwise it stays empty and the card says the maps show a mix. |
| Soil moisture (`smap.ts`, `ease2.ts`, `earthdata.ts`) | NASA SMAP L3 enhanced passive soil moisture `SPL3SMP_E` v006 (9 km, daily). Granules found through NASA CMR, then a 3×3 pixel window cut out through Earthdata Cloud OPeNDAP (`.dap.csv`) with the bearer token | Topsoil moisture (% water by volume, top ~2 in) from the newest pass in the last 10 days, a plain word (Dry / Good / Wet) and the 7-day average | 1 year per day file; CMR list 6 h | **Works** (2026-11-15): ~1.5 s per day. A spot is passed only every 2–3 days, so empty days (-9999) are skipped. A one-cell slice comes back empty from the CSV writer, hence the 3×3 window. The EASE-Grid 2.0 row/column maths was checked against the file's own latitude/longitude. |
| Satellite rainfall (`imerg.ts`) | NASA GPM IMERG Late daily `GPM_3IMERGDL` v07 (0.1°), same CMR + OPeNDAP route | Rain in the last 30 and 7 days and the wettest day (inches) | 1 year per day file | **Blocked on the account** (2026-11-15): GES DISC answers "EULA Acceptance Failure" until the account approves the *NASA GESDISC DATA ARCHIVE* application in its Earthdata profile. Farmers see "Not available yet" and the server console prints the approval link once. The parser is tested with the DAP4 CSV layout recorded from SMAP. |
| Crop greenness, NDVI (`ndvi.ts`) | NASA MODIS Terra MOD13Q1 (250 m, 16-day) via the ORNL DAAC MODIS web service, no login | Field-average NDVI for the newest clear composite and the same composite a year earlier | 7 days | Works (2026-11-14), 30–60 s per call, so the three calls run in parallel. |
| ZIP code lookup (`lib/server/zip.ts`) | US Census Bureau 2024 Gazetteer ZCTA internal points (bundled in `data/zcta.json`, public domain) | Centres the map on the ZIP area. A ZIP is only an area, so the farmer then pins or draws the field. | Bundled | Works offline. PO-box-only ZIPs have no ZCTA and get a clear "not found" message. Rebuild with `node scripts/build-zcta.mjs <gazetteer .txt>`. |
| Address search (`lib/server/geocode.ts`, `POST /api/geocode`) | US Census Bureau one-line address geocoder `geocoding.geo.census.gov/geocoder/locations/onelineaddress` (benchmark Public_AR_Current) | Moves the map to an address (Add a field, and the map search box). Up to 5 matches as a pick list. | 30 days | Works, ~1 s. No match is `addressMatches: []`; addresses over 100 characters get HTTP 400. Sent only after the farmer presses Find (no type-ahead), only when public data lookups are on, and in a POST body so it never appears in URLs. |
| Satellite imagery | USGS The National Map `basemap.nationalmap.gov/.../USGSImageryOnly/MapServer/tile` | Map background | Browser | Works. If the first tiles fail, the map switches to OpenStreetMap tiles and says so. |

## Privacy

Field boundaries are stored only in the browser (`localStorage`). To build a profile, the server sends the field's location (a point inside the field, sample points, or the boundary for the soil query) to NASA, USDA and USGS. A setting on the Fields screen ("Look up public data for my fields") turns all external lookups off.

## Caching

Responses are cached server-side in `web/.cache/` (JSON files keyed by request), with per-source time-to-live. Failed requests are never cached. In the browser, each source's result is stored with its fetch date; weather refreshes after a day, NDVI after a week, and soil and elevation never go stale. A changed boundary refetches everything. Each source has a Refresh / Try again button.

## Tests

`tests/unit/sources.test.ts` runs every module against responses recorded from the live endpoints on 2026-11-14 (`tests/fixtures/`), plus failure cases: HTTP errors, malformed bodies, empty results, partial point failures, the CDL fallback and circuit breaker, and Earthdata tokens that are missing, valid or rejected.
